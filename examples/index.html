x6-plugin-port-editor

给 AntV X6 加一个能力：点元件轮廓就能加引脚（端子）。 落点投影到元件**真实的 SVG 轮廓**（圆、多边形、自定义 path、直边、多图形拼合都行）， 不是包围盒，也不用你手算坐标。纯插件，**零核心改动、零运行时依赖**。

它替你解决什么问题

原以为要自己做的现在
手算每个端子的坐标 点一下轮廓即可；坐标由 SVG 的 CTM 链换算，平移 / 缩放 / 元件旋转都不用特判
端子在 resize 后跑位 positionUnit: 'local'（像素偏移）或 'percent'（相对位置）两种语义任选
只能给矩形元件加端子 任意轮廓：圆、多边形、自定义 path、直边（<line>）、 带孔洞的一条 path、矩形 + 两个圆的变压器符号 —— 见 例 3
端子外观、组名要改核心代码 全在插件选项里：group / idPrefix / groupConfig / outlineSelector
拖拽建端子要自己接 Dnd portEditor.createDndDropValidator() 一行接上（模板落到元件上变成端子，自身不落地）
加端子要能一步撤销 插件把"补组定义 + 加端子"合成一个 batch，接入 History 后是一步撤销
和 Selection / 拖拽层打架 点击与落点走 document.elementsFromPoint，能穿透选择框与拖拽层（已实测共存）

怎么引用（四种方式，按推荐顺序）

# ① 直接从 GitHub 装 —— npm 会 clone 并自动跑 prepare 构建出 dist
#    （本机已实测：装完 node_modules/x6-plugin-port-editor/dist/ 里 mjs/cjs/umd/d.ts 齐全）
npm install github:william-xue/x6-plugin-port-editor

# ② 锁到某个提交，可复现（机制同 ① ，未单独实测）
npm install github:william-xue/x6-plugin-port-editor#<commit-sha>

# ③ 只想要构建产物：把仓库里的 dist/ 拷进项目，零安装零编译
import { PortEditor } from './vendor/port-editor/index.mjs'

# ④ 只用源码：把 src/ 拷进项目（要求你的项目能编译 TS + 装了 @antv/x6）
import { PortEditor } from './vendor/port-editor/index'

不想用打包器也行 —— 直接用 UMD 产物，window.X6PluginPortEditor.PortEditor： 

<script src="x6/dist/x6.min.js"></script>
<script src="x6-plugin-port-editor/dist/index.umd.js"></script>

peerDependency：@antv/x6 >= 3.0.0（开发时实测 3.1.8）。 本仓库不发 npm，上面四条就是全部引用方式；细节与三个环境坑见 README.md §2.1。

例子（都在本仓库里，打开就能跑）

examples/ 是一个独立的消费方项目：它自己 npm install， 插件依赖直接从 GitHub 装进来（不是仓库里那份构建产物）—— 所以你看到的就是你自己项目里会长成什么样。

例 0 · 不接插件 vs 接上插件（先看这个） 左右两边是同一批元件（圆 CT / 六边形主变 / 圆角矩形断路器），差别只有一行 graph.use(portEditor)。左边演示手工成本并量出数字（估一个坐标 → 离真实轮廓 21.9 px；算准了 → 0 px，但每次换形状、每次 resize 都要重算），右边点一下轮廓就落在轮廓上。 点轮廓在左边是没有任何反应的。 例 1 · 最小接入（最简单） 已经有一个跑着的 X6 图，怎么把插件接上去：左侧列出「你原有的代码」与「新增的 8 行」， 代码与页面行为一一对应。含加引脚 / 从引脚拉线 / 悬停删除全链路。 例 3 · 难形状：能处理哪些轮廓 五种最容易"贴不上"的形状：直边 <line>、带孔洞的 <path>、 矩形+双圆（变压器）、同心圆环、开放折线。右侧列出插件实际读到了几条轮廓， 「轮廓可视化」把同一结果画到画布上。 例 4 · 端子接进你自己的数据 接进真实项目最容易卡住的不是"怎么加引脚"，而是"加完之后我的业务数据怎么办"。 这一页给完整闭环：端子增删 → 采成你自己的结构（右侧面板实时变）→ 清空 → 用那份数据重建回来。 例 2 · 电力组件场景（最完整） 自定义元件形状、项目自己的端子组与样式（T-1 编号）、调色板拖元件与拖端子、 与 Selection / History 共存（端子增删一步撤销）、导出 / 导入整图。 完整 demo · 带工具栏 元件调色板、连线样式（含潮流方向虚线动画）、JSON 导出/导入， 以及"从调色板拖一个引脚到元件上"的另一种入口。

本地怎么跑

git clone https://github.com/william-xue/x6-plugin-port-editor.git
cd x6-plugin-port-editor

# 例子是独立项目：装一次依赖（插件从 GitHub 装进来）
cd examples && npm install && cd ..

npm run demo         # 起静态服务（零依赖，端口 8732）
# 然后打开：
#   http://127.0.0.1:8732/examples/index.html          （本页）
#   http://127.0.0.1:8732/examples/00-before-after/     （用之前 vs 用之后）
#   http://127.0.0.1:8732/examples/03-hard-shapes/      （难形状）
#   http://127.0.0.1:8732/examples/04-host-state/       （接你自己的数据）
npm test             # 断言：轮廓缺陷门禁 + 插件 e2e + 例子 e2e（真实 Chrome）

没装 examples/node_modules 就打开页面？页面会直接告诉你去敲哪条命令（不会白屏）。 demo/ 那个页面走的是仓库自带的 dist/，用于开发本插件时的自测。

已知边界（诚实写在这里）

项状态
visibility:hidden 的形状 仍然参与落点（有尺寸就算候选）。用透明/隐藏矩形当"命中区"是常见做法， 一刀切跳过会把这类用法弄坏 —— 属设计取舍，尚未处理。
长轮廓上的拐角 均匀采样原本会在拐角处削掉一点（实测周长 1580 的元件偏 2.13）。 已修（v0.1.1）：拐角取两侧边的精确交点，四个拐角现在都偏 0。
引脚拖动调整位置 不做：与"从 magnet 拉线"是同一个手势，冲突未解（X6 issue #4648 / #4649）。
接线时自动生成引脚 刻意不做（设计红线）：端子是有编号/类型/方向的实体， 不该因为"手一抖拖了条线"就凭空多出来。入口必须是人明确要求的。

「难形状」那一页的五类形状都有常驻断言守着（npm run test:examples）， 其中直边与带孔洞两条是 2026-09-26 修掉的真实缺陷 —— 细节与前后对照数字见 test/EVIDENCE.md §6。

上游也有一个同源的 PR：antvis/X6#5093（把这套实现进 X6 内置插件目录）。 本仓库是它的可独立安装版本，也是它的对照实现。
